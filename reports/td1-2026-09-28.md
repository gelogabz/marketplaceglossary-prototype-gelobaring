## Recommended fixes

#### Snowflake Integration
- **Verdict:** stale
- **Rationale:** Current def claims "real-time streaming" of "entitlements, usage, revenue" into Snowflake. Live doc.suger.io/integrations/snowflake/ describes a narrower, different mechanic: automating tasks (SQL queries, row inserts/updates) inside a Snowflake account via key-pair auth — not a data-streaming pipe.
- **Draft:**
```js
def: "Suger's connection to Snowflake that lets ISVs automate tasks in their Snowflake account directly from Suger — executing SQL queries, inserting rows, and updating existing rows via key-pair authentication. Distinct from Snowflake Marketplace, which is for selling on Snowflake's own marketplace.",
```

#### Suger (flagship term)
- **Verdict:** stale
- **Rationale:** suger.io's homepage now states support for six marketplaces (AWS, Azure, Google Cloud, Snowflake, Alibaba Cloud, Oracle Cloud). The glossary's own top-level "Suger" def only lists four, omitting Alibaba and Oracle — both of which are otherwise fully covered elsewhere in the glossary. Real gap in the single most-referenced definition on the site.
- **Draft:**
```js
def: "A unified cloud marketplace platform enabling ISVs to list, transact, meter, and co-sell across AWS, Azure, GCP, Snowflake, Alibaba Cloud, and Oracle Cloud from a single interface, with integrations into CRM, billing, and communication tools.",
```

#### Azure Consumed Revenue (ACR) — Azure
- **Verdict:** dead_link
- **Rationale:** Cited source (`.../referrals/partner-reported-azure-consumed-revenue`) now 301-redirects to an unrelated July 2026 announcements page — that section of Partner Center docs was repurposed for the sales-leads "Referrals" feature. Live replacement found and confirmed: `learn.microsoft.com/en-us/partner-center/membership/solutions-partner-azure`, which currently defines ACR with concrete tier thresholds tied to Solutions Partner designation scoring.
- **Draft:**
```js
source: "https://learn.microsoft.com/en-us/partner-center/membership/solutions-partner-azure",
```

#### Deal Registration — Suger
- **Verdict:** stale + real correctness bug
- **Rationale:** Two issues found while checking against a Sept 26 Suger docs page: (1) def only describes the white-label-portal submission path; Suger now also supports a public deal-registration link requiring no portal login. (2) The `alias` field uses `"Related: Deal Registration — Azure"` instead of the required `"Azure equivalent: Deal Registration — Azure"` format — this is a real formatting bug that's been silently excluding this pair from the comparison table's union-find grouping.
- **Draft:**
```js
def: "The act of a partner — VAR, reseller, GSI, tech partner, or distributor — formally claiming credit for a deal with an ISV before or during an active sales cycle. In Suger PRM, a partner submits a deal registration through the white-label portal, or via a public link requiring no portal login; Suger automatically creates or updates a Salesforce Opportunity, routes the registration for ISV approval, and fires notifications so neither side loses track. Approved registrations protect the partner's margin and give the ISV a real-time view of partner-sourced pipeline alongside hyperscaler co-sell on the same CRM record.",
alias: "Azure equivalent: Deal Registration — Azure | Related: Partner Relationship Management (PRM) System, Value Added Reseller (VAR), Channel Partner (CP), Commission Tracking — Suger",
```

#### Request Private Offer — Azure ↔ Qualified Demo & Private Offer Requests — AWS
- **Verdict:** missing cross-platform link (zero risk — both terms already exist and are independently accurate)
- **Rationale:** These two existing terms describe the same buyer-initiated "request a private offer from the listing page" mechanism, but neither's alias cross-links to the other — the comparison table has no row for it. AWS's Sept 9 What's New entry (already reflected in the AWS term) prompted this cross-check.
- **Draft:** add `"Azure equivalent: Request Private Offer — Azure"` to `Qualified Demo & Private Offer Requests — AWS`'s alias, and `"AWS equivalent: Qualified Demo & Private Offer Requests — AWS"` to `Request Private Offer — Azure`'s alias.

## Recommended additions (score ≥ 3)

#### Marketplace Listing Retirement — cross-platform (new_term)
- **Why:** AWS, Microsoft, and Google Cloud each handle retiring a whole listing, a single plan, or one pricing dimension differently — different request types, different impact on existing buyers, different timelines. No existing term anywhere covers this lifecycle step; it's genuinely comparison-table-worthy (3 platforms, 3 different mechanics).
- **Source:** https://www.suger.io/resources/blog/retire-marketplace-listing/
- **Six-page impact:** Glossary ✓ | Comparison ✓ (new row) | others —

#### Marketplace Usage Correction — cross-platform (new_term)
- **Why:** Once a cloud accepts a usage record, there's no self-service way to reverse it — what recourse exists (if any) depends on the cloud and whether billing has already run. Same reasoning as above: real operational gap, 3-platform comparison potential, nothing currently documents it.
- **Source:** https://www.suger.io/resources/blog/marketplace-usage-correction/
- **Six-page impact:** Glossary ✓ | Comparison ✓ (new row) | others —

## Suggested (score 2, optional)

#### Know Your Customer (KYC) — AWS (new_term)
- AWS EMEA SARL invoices EMEA buyers only after the seller's KYC clears — and on a CPPO, only after the channel partner's KYC also clears. Until then, AWS Inc. invoices instead. "KYC" doesn't exist anywhere in the glossary as a concept.
- Source: https://www.suger.io/resources/blog/aws-emea-sarl-marketplace-kyc/

#### AWS EMEA SARL — AWS (updated_term)
- Same source as above — the existing def predates this KYC-gating rule entirely (which entity invoices a given transaction depends on KYC status).
- **Draft (append to def):** "Which entity invoices a given EMEA transaction depends on KYC status: AWS EMEA SARL invoices only once the seller's KYC has cleared — and on a Channel Partner Private Offer, only once the channel partner's KYC has also cleared — otherwise Amazon Web Services, Inc. invoices instead."

#### Growth Margins — Azure (updated_term)
- New capability: early-access API-based eligibility validation and discovery for CSP Growth Margins (currently the def only describes the incentive mechanism itself, not this new API path).
- **Draft (append to def):** "As of September 2026, partners can validate Growth Margin eligibility and discover applicable margins programmatically via API, in early access."
- Source: Azure Partner Center September 2026 announcements
